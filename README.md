# 네이버 블로그 매물 포스팅 자동화

네이버 매물정보, Kakao Local, 건축물대장 기초자료를 모아 매물 조사 메모와 블로그
원고를 만들고, 네이버 블로그에 **발행하지 않고 임시저장**하는 macOS·Windows용
로컬 프로그램입니다.

## 프로그램 폴더

현재 작업 폴더는 다음과 같습니다.

`/Users/ahn-bin/Documents/코중사제출용 프로그램`

macOS는 `run.command`, Windows는 `run.bat`로 실행합니다. 최초 한 번은 운영체제에
맞는 `scripts/setup.command` 또는 `scripts/setup.bat`를 실행합니다.

## 최종 작업 순서

1. **1. 샘플/매물 미리보기 (Google AI 미사용)**
   - 매물번호가 있으면 실제 수집을, 비어 있으면 내장 샘플을 사용합니다.
   - 네이버 매물 기본정보, 면적 계산, Kakao 주변시설·Daum 웹검색 참고자료,
     건축물대장 표제부를 모읍니다.
   - Gemini를 호출하지 않으며 `blog자료`의 기존 제목·본문을 덮어쓰지 않습니다.
   - 결과는 하나로 병합된 `매물 조사 메모`에 표시됩니다.
2. **2. 콘텐츠 자동 생성**
   - 방금 수집한 같은 매물의 자료로 제목·본문·해시태그를 생성해 `blog자료`에 넣습니다.
   - 1단계의 Kakao·Daum 참고자료를 재사용해 Google Search grounding을 추가 호출하지
     않고, 게시물당 Gemini 텍스트 생성 요청을 한 번으로 제한합니다.
   - Google AI Studio 키가 없거나 무료 할당량이 끝나면 수집 자료 기반 로컬 초안으로
     자동 전환합니다.
3. **3. 대표 이미지 생성 (로컬·무료)**
   - `이미지` 탭의 프롬프트에서 색상과 문구 배치를 수정할 수 있습니다.
   - 외부 이미지 API를 호출하지 않고 Pillow로 1080×1080 PNG를 만듭니다.
4. **4. 검토한 글을 임시저장**
   - 현재 화면에서 사용자가 수정한 제목·본문·태그를 고정 원고 파일에 다시 저장합니다.
   - 필요하면 네이버에 자동 로그인한 뒤 제목, 본문 서식, HTML 표, 대표 이미지,
     전화 배너, 거래상태 확인 이미지를 입력하고 임시저장합니다.
   - 자동 발행은 하지 않으며 완료 뒤 Chrome 창을 그대로 열어 둡니다.

모든 입력칸과 결과 텍스트는 선택 후 Windows/Linux `Ctrl+C`, macOS `⌘C`로 복사할
수 있습니다. 붙여넣기는 `Ctrl+V`, `⌘V`, `Shift+Insert`와 화면 버튼을 지원합니다.

## 환경설정

`환경설정` 탭에서 다음을 한곳에서 관리합니다.

- Google AI Studio API Key
- Kakao REST API 키
- Kakao JavaScript 키
- 공공데이터포털 서비스키
- 네이버 로그인 ID, 네이버 비밀번호, 실제 블로그 ID, 문의번호
- 선택 항목인 이실장 ID·비밀번호
- 비밀번호 보안 저장 여부

네이버 로그인 ID와 블로그 ID가 같다면 블로그 ID를 비워도 됩니다. 프로그램은
`https://blog.naver.com/[실제 블로그 ID]?Redirect=Write`를 매번 다시 계산합니다.
`agent-kang`, `green-core` 같은 예시 계정을 고정해서 사용하지 않습니다.

비밀번호 원문은 YAML·JSON·로그에 저장하지 않습니다. 보안 저장을 선택한 경우에만
macOS Keychain 또는 Windows 자격 증명 저장소를 이용합니다. API 키는 Git에서 제외된
로컬 `.env`에 저장합니다.

Kakao JavaScript SDK의 허용 도메인에는 아래 주소를 등록합니다.

`http://localhost:8765`

지도와 로드뷰는 프로그램의 같은 `지도·로드뷰` 탭에서 전환됩니다. 공식 카카오맵과
공식 로드뷰를 별도 브라우저에서 확인하는 버튼도 함께 제공합니다.

## 네이버 403·429 대응

일반적인 사용에서는 `문제 해결·고급 설정` 탭을 열 필요가 없습니다.

프로그램은 `httpx.Client`에서 실제 Chrome과 유사한 `User-Agent`, `Accept` 관련
헤더를 사용하고, 상세 페이지 응답으로 생성된 `PROP_TEST_*` 등의 쿠키를 메모리에
유지한 뒤 매물 API를 호출합니다. 401·403 또는 짧은 429가 발생하면 새 응답 쿠키를
반영하고 제한적으로 재시도합니다. 쿠키는 파일이나 로그에 기록하지 않습니다.

API가 계속 차단되면 숨겨진 Chrome으로 공개 매물 상세 화면에 표시되는 데이터를
읽습니다. 이것도 실패할 때만 개발자 도구 Network에서 매물 상세 요청을
**Copy as cURL**로 복사해 `문제 해결·고급 설정`에 붙여 넣습니다. 이 cURL도
현재 프로그램 메모리에만 존재합니다.

## 조사 데이터

Kakao REST 키가 있으면 주소 좌표를 기준으로 지하철역, 학교, 학원, 마트, 편의점,
병원, 약국, 문화시설, 공원, 버스정류장 등을 조회합니다. 거리는 경로 거리가 아닌
직선거리이므로 원고에도 그 사실을 표시합니다.

같은 REST 키로 Daum 웹검색의 제목·요약·원문 링크를 수집해 개발계획, 학군,
단지정보, 교통·생활편의 참고자료로 보여 줍니다. 검색 결과 자체는 사실로 확정하지
않으며 원문·기준일 확인 전에는 단정적인 문장으로 쓰지 않습니다.

공공데이터포털 키가 있으면 건축물대장 표제부를 조회합니다. 숫자 `0`, 빈 값,
`정보 없음` 필드는 조사 메모와 HTML 표에서 생략합니다. 표제부는 건물 단위 자료이며
개별 호실의 권리관계나 현 상태를 증명하지 않습니다.

## 프롬프트 변경과 기본값 복원

`기본 글 작성 프롬프트`와 `이미지` 탭에서 각각 프롬프트를 편집하고 저장할 수 있습니다.
저장 내용은 `config/user_settings.json`에 기록됩니다. 각 탭의 **기본값 복원** 버튼은
프로그램에 내장된 최초 기준으로 되돌립니다.

환경변수 또는 UTF-8 텍스트 파일로도 프롬프트를 공급할 수 있습니다.

```bash
export BLOG_WRITING_PROMPT="사용자 글 작성 기준"
export BLOG_WRITING_PROMPT_FILE="/absolute/path/blog_prompt.txt"
export IMAGE_GENERATION_PROMPT="사용자 이미지 기준"
export IMAGE_GENERATION_PROMPT_FILE="/absolute/path/image_prompt.txt"
```

파일 환경변수가 있으면 파일 내용을, 없으면 직접 값 환경변수를 읽습니다. 명시된
환경변수는 앱에서 저장한 사용자 설정보다 우선합니다. 환경변수를 제거하면 다시 UI에서
저장한 값을 사용하므로 운영 시에는 한 방식을 정해 사용하는 것이 좋습니다.

## 비용 0 운영 원칙

- 1단계 미리보기는 Gemini를 전혀 호출하지 않습니다.
- 3단계 이미지는 항상 로컬에서 생성하며 Gemini 이미지 모델 설정을 무시합니다.
- 유료 모델 자동 전환, 유료 이미지 API, 자동 결제 전환은 없습니다.
- Google AI Studio 키가 없으면 2단계도 로컬 초안으로 처리합니다.
- Gemini를 쓸 때는 사용자가 제공한 무료 등급 키와 `gemini-3.5-flash`만 사용하고,
  기본 요청 시작 간격을 12.5초로 제한합니다. 콘텐츠 한 건당 텍스트 생성은 한 번만
  호출합니다.
- `429 RESOURCE_EXHAUSTED`에는 일일 한도를 계속 재시도하지 않고 로컬 초안으로
  전환합니다.

중요: 프로그램은 Google Cloud 프로젝트의 결제 연결 상태를 변경하거나 확인할 수
없습니다. **절대적인 과금 방지**가 필요하면 결제가 연결되지 않은 무료 등급 프로젝트의
키만 사용하거나 Google 키를 비워 두어야 합니다. Kakao·공공데이터도 각 서비스의 무료
쿼터와 이용약관 범위에서 사용해야 합니다.

남은 Gemini 호출 수는 앱에서 추정해 표시하지 않습니다. RPM·TPM·RPD가 프로젝트
단위로 합산되어 로컬 카운터가 실제 값과 달라질 수 있기 때문입니다. 대신 환경설정의
**사용량 확인** 버튼으로 Google 공식 화면을 엽니다.

## 생성 파일

- 블로그 원고: `output/contents/blog_[매물번호].md`
- 대표 이미지: `output/thumbnails/thumbnail_[매물번호].png`
- 실행 원자료: `output/[날짜-시간-매물번호]/`
- 셀렉터: `config/blog_selectors.yaml`
- 계정·게시 설정: `config/settings.yaml`
- 비밀키: `.env` (Git 제외)

원고에는 아래 플레이스홀더가 정확히 한 번씩 들어갑니다.

```text
[THUMBNAIL_IMAGE]
[TABLE_COMPLEX]
[TABLE_SUMMARY]
[TABLE_DETAIL]
[TABLE_REALTOR]
```

임시저장 시 플레이스홀더는 매물·단지·중개사 정보 HTML 표로 변환됩니다. HTML 표 직접
삽입이 현재 네이버 에디터에서 거부되면 같은 정보를 탭 구분 텍스트로 넣고 로그에
안내합니다.

## 자동 게시 안전장치

- `config/blog_selectors.yaml`의 동적 클래스·의미 기반 후보를 순서대로 사용합니다.
- 작성 중인 글 복구 팝업과 임시저장 버튼을 가리는 도움말 패널을 닫습니다.
- 네이버 추가 인증이나 CAPTCHA는 사용자가 열린 창에서 완료해야 합니다.
- 임시저장 성공 전에 사용자가 Chrome을 닫으면 친절한 오류로 처리합니다.
- 임시저장 후 창을 닫는 것은 정상 종료로 처리하며 Playwright 원문 오류를 띄우지
  않습니다.
- 발행 버튼은 누르지 않습니다.

## 테스트

```bash
PYTHONPATH=.:.venv/lib/python3.14/site-packages pytest -q
```

현재 자동 테스트는 설정, 키 붙여넣기, 매물번호 붙여넣기, 쿠키·429 처리,
조사 데이터, 고정 원고, HTML 표, 로그인·임시저장 안전장치, 4단계 워크플로우를
검증합니다. 실제 네이버 계정의 에디터 UI는 서비스 변경 가능성이 있으므로 최종
실계정 임시저장은 사람의 확인이 필요합니다.

다른 개발자나 AI에게 넘길 때는 [HANDOFF.md](HANDOFF.md)를 함께 전달하세요.
