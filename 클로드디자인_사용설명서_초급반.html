01 클로드 디자인이란

한 줄로: 차갑고 복잡한 화면 대신, 따뜻한 종이 위에 꼭 필요한 것만 놓는 방식입니다.

대부분의 프로그램은 파란색과 회색을 씁니다. 파란 헤더, 파란 버튼, 회색 배경. 안전하지만 기계 같고, 무엇이 중요한지 알기 어렵습니다. 클로드 디자인은 정반대로 갑니다.

따뜻한 바탕

순백색이나 차가운 회색 대신 살짝 크림빛이 도는 종이색(#FAF9F5)을 씁니다. 눈이 덜 피로하고, 화면이 문서처럼 읽힙니다.

강조색은 딱 하나

따뜻한 주황빛 코럴(#D97757) 하나만 강조색으로 씁니다. 화면에서 코럴이 보이면 "여기를 누르세요"라는 뜻이 됩니다.

선은 거의 안 보이게

두꺼운 테두리와 그림자 대신 아주 연한 1px 선으로만 영역을 나눕니다. 선이 조용해야 내용이 살아납니다.

여백이 곧 디자인

화면을 꽉 채우지 않습니다. 넉넉한 여백이 "이건 하나의 묶음"이라고 선 없이 말해줍니다.

초급자가 기억할 단 하나

디자인을 잘한다는 건 예쁜 색을 고르는 게 아니라 같은 규칙을 반복하는 것입니다. 색 4개, 글자 크기 6개, 여백 5개만 정해놓고 그 안에서만 고르세요. 그것만으로 화면이 정돈됩니다.

02 우리 프로그램 Before / After

지금 만드시는 vibe-blogpost-free 화면을 실제로 바꿔본 결과입니다. 레이아웃은 그대로 두고 색·글자·여백만 바꿨습니다.

같은 코드, 다크 모드까지

색을 이름(토큰)으로 바꿔두면 다크 모드는 한 줄로 됩니다. 위젯 코드는 하나도 안 고칩니다.

03 색 — 규칙 세 가지

색은 "예쁜 색 고르기"가 아니라 역할 나누기입니다.

규칙 1 · 60 : 30 : 10

화면 면적을 이 비율로 씁니다. 강조색이 10%를 넘으면 강조가 아니게 됩니다.

비율역할무엇에
60%바탕창 배경, 카드 배경 — 크림·흰색
30%글자·선본문, 제목, 구분선 — 진회색·연한 선
10%강조주 버튼, 진행바, 선택 표시 — 코럴

규칙 2 · 색은 이름으로 부른다

코드에 #16344c라고 직접 쓰면, 나중에 색을 바꿀 때 163,000자짜리 app.py를 전부 뒤져야 합니다. 역할 이름을 붙여두면 한 곳만 고치면 됩니다.

✗ 이렇게 하지 마세요

bg="#16344c"

fg="#2b6f8a"

이게 무슨 색인지, 왜 이 색인지 3개월 뒤엔 본인도 모릅니다.

✓ 이렇게 하세요

bg=C.INK

fg=C.CORAL_DEEP

"어두운 면", "주 버튼 색"이라고 읽힙니다. 다크 모드도 공짜로 따라옵니다.

규칙 3 · 색만으로 뜻을 전하지 않는다

색맹인 분(남성 20명 중 1명)에게 빨강·초록은 같은 색입니다. 색 + 글자를 함께 쓰세요. "✓ 완료", "⚠ 확인 필요"처럼요.

왜 코럴이 두 개인가요?

브랜드 코럴 #D97757 위에 흰 글자를 올리면 명암 대비가 3.1:1밖에 안 됩니다. 국제 접근성 기준(WCAG AA)은 본문 글자에 4.5:1을 요구합니다. 그래서 글자를 얹는 면에는 한 톤 진한 #BC5A38(4.51:1)을 씁니다. 글자가 없는 진행바·아이콘에는 밝은 #D97757을 그대로 쓰면 됩니다.

상태색 — 뜻이 있을 때만

✓ 완료 ⚠ 확인 필요 ✕ 실패 ⓘ 안내

같은 초록이라도 면에 쓰는 색과 글자에 쓰는 색은 다릅니다. 연한 배경 위 글자는 더 진해야 읽힙니다 → SUCCESS(면 #4F7A55) / SUCCESS_TEXT(글자 #3E6344)

04 글자 — 크기로 위계 만들기

중요한 걸 크게, 덜 중요한 걸 작게. 색을 알록달록하게 하는 대신 크기와 굵기로 순서를 만듭니다.

크기는 6단계만

단계가 많으면 오히려 헷갈립니다. Tkinter는 pt 단위를 씁니다.

SIZE_DISPLAY · 26 bold 앱 제목
SIZE_H1 · 20 bold 화면 제목
SIZE_H2 · 15 bold 구역 제목
SIZE_H3 · 13 bold 카드 제목
SIZE_BODY · 12 본문 — 대부분의 글자
SIZE_SMALL · 11 버튼 글자, 라벨
SIZE_CAPTION · 10 도움말, 표 머리글

글꼴은 하나로 통일

클로드는 제목에 세리프(명조 계열), 본문에 산세리프(고딕)를 섞습니다. 하지만 한글 데스크톱 앱에서는 고딕 하나로 통일하는 편이 안전합니다 — 설치된 세리프 한글 글꼴이 컴퓨터마다 다르기 때문입니다. 대신 크기 차이를 크게 벌려서 같은 효과를 냅니다 (26 vs 12 = 2배 이상).

운영체제별로 알아서 고르게 하기
# 설치된 글꼴 중 앞선 후보를 자동으로 고른다
from tkinter import font as tkfont

PREFERRED = ("Pretendard", "Apple SD Gothic Neo",   # macOS
             "Malgun Gothic", "Noto Sans KR")        # Windows

installed = set(tkfont.families(root))
SANS = next((f for f in PREFERRED if f in installed), "TkDefaultFont")
한글은 영문보다 커 보여야 합니다

같은 12pt라도 한글은 영문보다 빽빽해 보입니다. 본문은 12pt 이상, 도움말도 10pt 밑으로 내려가지 마세요. 줄 간격도 영문 기준보다 넉넉히 잡습니다.

05 여백 — 4의 배수만 쓴다

여백을 7, 13, 22처럼 눈대중으로 넣으면 화면이 미묘하게 어긋납니다. 4의 배수 5개만 정해놓고 그중에서 고르세요.

XS · 4
SM · 8
MD · 12
LG · 16
XL · 24
XXL · 32
쓸 곳값설명
줄 사이S.SM = 8라벨과 입력창처럼 딱 붙은 한 쌍
항목 사이S.MD = 12같은 묶음 안의 줄과 줄
카드 안쪽S.PAD_CARD = (20,18)카드 테두리와 내용 사이
카드 사이S.LG = 16카드와 카드
창 가장자리S.PAD_PAGE = 28창 테두리와 내용 사이

가까운 것끼리 붙인다 (근접성의 법칙)

선을 긋지 않아도 여백만으로 묶음을 만들 수 있습니다. 관련 있는 것은 가깝게, 관련 없는 것은 멀리.

✗ 전부 같은 간격

제목 — 10 — 입력창 — 10 — 제목 — 10 — 입력창

어느 제목이 어느 입력창의 것인지 알 수 없습니다.

✓ 묶음 안은 좁게, 묶음 사이는 넓게

제목 — 8 — 입력창 — 24 — 제목 — 8 — 입력창

선 하나 없이도 두 묶음으로 보입니다.

06 모서리와 선

Tkinter의 한계와 해결책

ttk 위젯은 모서리를 둥글게 못 합니다

CSS의 border-radius 같은 옵션이 ttk에는 없습니다. 방법은 두 가지입니다.

방법 A · 각진 채로 두기 (권장)

각진 모서리 + 연한 1px 테두리 + 넉넉한 여백이면 클로드 느낌의 80%는 나옵니다. 위 After 화면이 이 방식입니다. 코드가 단순하고 버그가 없습니다.

방법 B · Canvas로 직접 그리기

정말 둥근 버튼이 필요하면 tk.Canvas에 둥근 사각형을 그립니다. 제공해 드린 RoundedButton이 그것입니다. 화면당 1~2개(주 버튼)에만 쓰세요.

둥근 사각형 그리기 — smooth=True 가 핵심
def rounded_rect(canvas, x1, y1, x2, y2, r, **kw):
    points = [x1+r, y1, x2-r, y1, x2, y1, x2, y1+r,
              x2, y2-r, x2, y2, x2-r, y2, x1+r, y2,
              x1, y2, x1, y2-r, x1, y1+r, x1, y1]
    return canvas.create_polygon(points, smooth=True, **kw)

그림자 대신 선

클로드 디자인은 그림자를 거의 안 씁니다. Tkinter에서 그림자는 어차피 흉내 내기 어려우니 잘된 일입니다. 연한 선 #E6DFD8 하나로 카드를 구분하세요. 선이 진하면 화면이 답답해집니다.

07 부품별 규칙

버튼 — 종류는 4개면 충분

종류스타일 이름언제
주 버튼Primary.TButton 화면에서 가장 하고 싶은 일 딱 하나. 코럴 채움
보조 버튼Secondary.TButton 그 외 일반 동작. 흰 바탕 + 연한 테두리
고스트 버튼Ghost.TButton 있어도 그만인 동작(초기화, 닫기). 배경 없음
위험 버튼Danger.TButton 되돌릴 수 없는 삭제. 빨강. 아껴 쓰기
주 버튼은 화면당 1개

Before 화면에는 색이 채워진 버튼이 5개였습니다. 5개가 전부 "나를 눌러"라고 외치면 사용자는 아무것도 고르지 못합니다. 진행 상태 표시(진행 중=주황, 완료=초록)는 예외입니다 — 그건 버튼이 아니라 상태 표시니까요.

입력창 — 테두리는 포커스로 말한다

평소엔 연한 회색 테두리, 커서가 들어가면 코럴 테두리로 바뀝니다. 어디를 입력 중인지 한눈에 보입니다.

ttk.Entry — 포커스 시 테두리 색 바꾸기
style.configure("TEntry",
    fieldbackground=C.SURFACE, foreground=C.TEXT_STRONG,
    bordercolor=C.LINE, insertcolor=C.CORAL,
    padding=(12, 9), relief="flat", borderwidth=1)
style.map("TEntry",
    bordercolor=[("focus", C.CORAL)],   # 커서 들어오면 코럴
    lightcolor=[("focus", C.CORAL)],
    darkcolor=[("focus", C.CORAL)])
clam 테마를 꼭 쓰세요

style.theme_use("clam")을 부르지 않으면 macOS·Windows 기본 테마가 배경색·테두리색 지정을 무시합니다. 색이 안 먹으면 십중팔구 이것 때문입니다.

카드 — 화면을 덩어리로 나누기

긴 화면은 카드로 자릅니다. 카드 하나 = 할 일 하나. "1단계 · 매물 정보", "2단계 · 실행"처럼요.

Tkinter에서 1px 테두리 카드 만들기 (테두리색 프레임 + 흰 속 프레임)
class Card(tk.Frame):
    def __init__(self, master, padding=(20, 18)):
        # 바깥 프레임 = 테두리 색으로 칠한 1px 액자
        super().__init__(master, bg=C.LINE, bd=0, highlightthickness=0)
        # 안쪽 프레임 = 실제 내용이 들어갈 흰 면
        self.body = tk.Frame(self, bg=C.SURFACE, bd=0, highlightthickness=0)
        self.body.pack(fill="both", expand=True, padx=1, pady=1)
        self.body.configure(padx=padding[0], pady=padding[1])

# 사용
card = Card(parent); card.pack(fill="x", pady=16)
ttk.Label(card.body, text="1단계 · 매물 정보", style="H3.TLabel").pack(anchor="w")

표 (Treeview) — 줄은 넉넉히

기본 rowheight는 한글에 너무 좁습니다. 30 이상으로 키우고, 머리글은 배경만 살짝 다르게 두세요. 선택된 줄은 CORAL_SOFT로 표시합니다.

진행 표시 — 얇게

진행바 두께는 6px이면 충분합니다. 굵으면 화면을 잡아먹습니다. 색은 밝은 CORAL(글자가 없으니 그대로 써도 됩니다).

08 화면 만드는 순서

새 화면을 만들 때 이 순서대로 하면 헤매지 않습니다.

  • 1. 이 화면에서 사용자가 할 일 하나를 정한다. → 그게 주 버튼입니다.
  • 2. 필요한 정보를 종이에 다 적는다. 화면 생각 말고 목록만.
  • 3. 목록을 3~5개 묶음으로 나눈다. → 묶음 하나가 카드 하나.
  • 4. 묶음에 순서를 준다. 위에서 아래로 사용자가 하는 순서대로.
  • 5. 색 없이 회색으로만 배치해 본다. 크기·여백만으로 위계가 보이는지 확인.
  • 6. 마지막에 코럴을 딱 한 군데 칠한다. 주 버튼.
  • 7. 창을 반으로 줄여본다. 깨지면 fill·expand를 손봅니다.
5번이 핵심입니다

회색만으로 위계가 안 보이면, 색을 칠해도 안 보입니다. 색은 이미 잘 정리된 화면을 강조할 뿐, 어지러운 화면을 고쳐주지 않습니다.

09 초보가 자주 하는 실수 7가지

1. 색을 코드에 직접 쓴다

bg="#16344c" → 색 하나 바꾸려고 파일 전체를 찾아 헤맵니다. 토큰 상수를 쓰세요.

2. 강조색을 여기저기 칠한다

버튼 5개가 다 색이 있으면 강조가 아니라 소음입니다. 주 버튼은 화면당 하나.

3. 여백을 눈대중으로 넣는다

pady=7, pady=13이 섞이면 미묘하게 어긋나 보입니다. 4의 배수만.

4. 테두리를 진하게 그린다

relief="raised", 두꺼운 회색 선 → 1990년대 화면이 됩니다. 연한 1px 선 하나.

5. 글자 크기를 3개만 쓴다

전부 10pt·11pt면 무엇이 중요한지 알 수 없습니다. 제목은 과감하게 크게.

6. 화면을 꽉 채운다

빈 공간이 아까워 위젯을 밀어 넣습니다. 여백은 낭비가 아니라 기능입니다.

7. 대비를 확인하지 않는다

연한 회색 글자는 본인 모니터에서만 잘 보입니다. 본문은 4.5:1 이상.

보너스 · theme_use("clam") 빼먹기

색 지정이 통째로 무시됩니다. "왜 색이 안 바뀌지?" 싶으면 여기부터 확인하세요.

⑤ 명암 대비 자가 점검

새 색을 만들었을 때 이 코드로 확인하세요. 본문 4.5 이상이면 합격입니다.

def contrast(fg, bg):
    def lum(h):
        h = h.lstrip("#")
        c = [int(h[i:i+2], 16) / 255 for i in (0, 2, 4)]
        c = [v/12.92 if v <= 0.04045 else ((v+0.055)/1.055)**2.4 for v in c]
        return 0.2126*c[0] + 0.7152*c[1] + 0.0722*c[2]
    a, b = sorted([lum(fg), lum(bg)], reverse=True)
    return (a + 0.05) / (b + 0.05)

print(contrast("#FFFFFF", "#BC5A38"))   # 4.51 → 합격
print(contrast("#FFFFFF", "#D97757"))   # 3.12 → 불합격

11 우리 프로그램에 적용하기

전부 한 번에 바꾸지 마세요. 3단계로 나누면 되돌리기도 쉽습니다.

1단계 · 파일 넣고 한 줄 바꾸기 (5분)

claude_theme.py를 app.py와 같은 폴더에 넣고, _configure_style 안의 내용을 apply_claude_theme(self.root) 한 줄로 바꿉니다.

기존 스타일 이름(Primary.TButton, White.TFrame 등)을 그대로 유지했으므로 위젯 코드는 손댈 필요가 없습니다. 실행해서 전체 색이 바뀌는지 확인하세요.

2단계 · 하드코딩된 색 치환 (30분)

bg=, fg=, background=, foreground=에 직접 적힌 색 코드를 위 ④번 표대로 토큰으로 바꿉니다.

# 남은 하드코딩 색 찾기 (터미널)
grep -n '#[0-9a-fA-F]\{6\}' app.py

3단계 · 카드로 다시 묶기 (1~2시간)

ttk.LabelFrame으로 되어 있는 구역들을 Card로 바꾸고, 여백을 S. 상수로 정리합니다. 그리고 채워진 버튼을 세어보세요 — 주 버튼 1개 + 진행 상태 표시만 남기면 됩니다.
